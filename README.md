# Micronaut Data 5.2: repository compiled without queries when its record entity's static method returns a generated type

On Micronaut Platform 5.2.0 (Micronaut Data 5.2.0), a JDBC repository whose
record entity declares a static method returning a type that another annotation
processor generates in the same compilation is compiled without its
compile-time queries. Compilation succeeds with no error or warning; each
affected method fails when called with:

```
java.lang.IllegalStateException: Micronaut Data method is missing compilation time query information. Ensure that the Micronaut Data annotation processors are declared in your build and try again with a clean re-build.
```

On Platform 5.1.5 (Micronaut Data 5.1.4) the same code works.

This project was generated by [Micronaut Launch](https://launch.micronaut.io)
with the `data-jdbc` feature and trimmed to Micronaut Data JDBC, H2, and
[RecordBuilder](https://github.com/Randgalt/record-builder), which generates a
`<Record>Builder` class for each record annotated `@RecordBuilder`.

## The two entities

- `Widget` declares `static WidgetBuilder named(String)`, so a method signature
  names the generated builder type.
- `Gadget` is the control: it uses its generated builder only inside a method
  body, and its factory returns the record itself.

Each has a `@JdbcRepository(dialect = Dialect.H2)` extending `CrudRepository`.
`RepositoryQueryTest` reads each repository's compiled bean definition and lists
the abstract methods that carry no `@DataMethod` interceptor. It does not start an
application context.

## Reproduce

```bash
./gradlew test                            # Platform 5.2.0: WidgetRepository fails
./gradlew test -PmicronautVersion=5.1.5   # Platform 5.1.5: both pass
```

On 5.2.0:

```
RepositoryQueryTest > repositoryOfAnEntityWhoseStaticMethodReturnsAGeneratedTypeHasItsQueries() FAILED
    org.opentest4j.AssertionFailedError: expected: <[]> but was: <[count, delete, deleteAll, deleteAll, deleteById, existsById, findAll, findById, findByName, insert, insertAll, save, saveAll, update, updateAll]>
```

| Platform | Micronaut Data | `WidgetRepository` | `GadgetRepository` |
|---|---|---|---|
| 5.1.5 | 5.1.4 | every method has its query | every method has its query |
| 5.2.0 | 5.2.0 | 15 methods without a query | every method has its query |

## Related

The same record also gets no bean introspection on 5.2.0. That is a separate
Micronaut Core regression, reproduced in
[micronaut-generated-type-introspection-repro](https://github.com/moltenbits/micronaut-generated-type-introspection-repro).
Fixing it does not fix this one: with a Core processor patched for the
introspection bug, `WidgetRepository` still has no queries.

## Environment

- JDK 25.0.3 (GraalVM)
- Gradle 9.6.0
- Micronaut Gradle plugin 5.0.2
- RecordBuilder 53
